# MCP

Nivra exposes an authenticated MCP endpoint at `/mcp`. Open **Settings → MCP** to copy its URL, create a bearer API key, inspect OAuth clients, or revoke access. Choose **New key** to open the key form; choose Read (the default) or Read & write. Write access always includes reading. An optional expiry is entered in days; leaving it blank creates a key without automatic expiry. A valid owner session is sufficient to manage MCP credentials; no repeated verification or sign-out is required. API keys are shown once and stored as hashes; put them in the `Authorization: Bearer …` header, never in a URL.

Read-only connections receive `nivra:read`. Read & write access adds `nivra:write`, including publication and moving active items to Trash. Agents can list Trash, but cannot modify or restore trashed items or permanently delete them; those actions remain in the human UI. Account credentials, recovery, server configuration and full-instance backups remain browser/operator operations. Browser cookies do not authenticate MCP. Bearer API keys also authenticate scoped `/api/v1` content routes; OAuth tokens remain limited to MCP. Administrative routes require an owner session.

## Connecting

OAuth consent offers the same Read / Read & write choice, defaulting to Read. The initial MCP authentication challenge requests both scopes so clients can offer the full choice. Clients explicitly requesting only reading cannot be upgraded during consent. Read-only grants expose only read tools; reconnect and approve Read & write to use creation and editing tools.

Use `count_items` for exact totals, active/Trash counts, tag counts, favorites, and open/completed task totals. It counts in SQLite within one snapshot rather than fetching content pages. Notes and journals are separate; templates are excluded. Favorites apply to notes, journals, bookmarks and forms. `search` returns bounded relevant matches; `search_items` provides exact indexed match totals and pagination without fuzzy fallback, including `type:journal` and tag filters. Follow list responses' `next` cursor as `after`, or `nextOffset` as `offset`, until null. Tags and Favorites use `nextOffset`. Read `item_tags` before replacing tag assignments. MCP's tool discovery and server instructions describe this workflow without a duplicate documentation tool.

Tool inputs reject unknown fields and empty patches. Core item/count/page responses have explicit schemas and are validated before returning. Operation failures include `isError` and structured status/code/retryability metadata; the SDK rejects invalid tool inputs before execution. `file_transfer` returns read/download routes; `upload_transfer` requires write access and returns the upload method, content type and any required form fields. These bundle transfers are content exports/imports, not operator backups with account secrets.

Indexed matching uses SQLite FTS word prefixes joined with AND, up to 20 search terms. Longer exhaustive queries are rejected rather than truncated. Offset pages use a deterministic order; edits between requests can change their contents, so use item IDs to deduplicate a changing inventory.

For a local agent, use the HTTP MCP URL and a key created in Settings. Keep keys in the client's credential store. For a remote OAuth client, set `NIVRA_PUBLIC_URL` to the installation's HTTPS origin. No separate OAuth environment variables are required. The authorization server uses the owner's existing password/passkey and optional TOTP login, then shows explicit consent. OAuth tokens are resource-bound, expire after 15 minutes, and may refresh when `offline_access` was approved. Disconnecting an OAuth client invalidates its registered access tokens, refresh grants, consent and pending authorization codes. Account recovery also revokes agent access.

Discovery is available at `/.well-known/oauth-protected-resource/mcp` and `/.well-known/oauth-authorization-server/api/auth`. Nivra supports verified Client ID Metadata Documents and automatic Dynamic Client Registration at `/api/auth/oauth2/register`. Manual client registration is not exposed in Settings. Registration does not grant access: the owner must sign in and approve the client, and authorization requires S256 PKCE. Public clients and confidential clients are supported. HTTPS callbacks and native loopback HTTP callbacks are accepted; omitted application types are inferred as native for loopback HTTP callbacks. Registration requests are bounded to 16 KiB, ten callback URLs, rate limits, and 200 clients without owner consent. Callback and scope validation remain enforced by Better Auth. Bearer API keys remain available for clients without OAuth support.

The official TypeScript SDK serves protocol version `2026-07-28` with stateless compatibility for older Streamable HTTP clients. Requests use `POST /mcp`; responses may be JSON or request-scoped SSE. There is no separate legacy `/sse` endpoint or persistent session requirement. Clients must accept `application/json` and `text/event-stream`. Connections are limited to 120 authenticated requests per minute; retry after a `429` response. Remote client compatibility still depends on that client's transport and OAuth support.

## Content operations

Tool discovery reflects the connection's permissions. Tools cover notes and journals, tasks, calendar events and reminders, bookmarks, artifacts, tags, favorites, search, revision history, connected items, publication, moving active items to Trash, and read-only Trash listing. Search includes indexed artifact extraction; list tools return bounded summaries. Read complete content only when needed. Background extraction and bookmark metadata use the existing durable SQLite queue; `processing_status` reports their progress. Agent changes invalidate browser lists through the existing SSE stream. Dirty editor content is preserved and reports a conflict rather than silently adopting an external revision.

`list_calendar` returns exact per-day counts and paged occurrences for a date range and timezone; `includeCompleted` controls completed tasks. `list_calendar_tasks` lists overdue or undated open tasks with an exact total and pagination. `get_task_reminders` reads saved task reminder settings; `set_task_reminders` changes them (empty offsets disable that schedule). `get_event`, `create_event`, `update_event` and `trash_event` manage standalone and linked schedules. Recurring edits specify `series`, `occurrence` or `following`; occurrence edits require the returned occurrence key. Tasks accept date-only `plannedDate` and `dueDate`. Reminder tools manage saved schedules and the reminder list; device subscriptions remain browser-only. Event creation returns its canonical `/calendar?event=…` URL.

BlockNote JSON remains canonical. `append_note` and `edit_note_blocks` preserve untouched rich blocks. Markdown is an optional, lossy input format parsed in a bounded worker; `replace_note_content` explicitly replaces a whole document. Every revision-sensitive mutation requires the current revision. Journals remain unique per calendar date, and supplying initial content for an existing journal is rejected.

Creation tools accept an optional `idempotencyKey` (8–128 characters). Repeating identical input on the same connection returns its saved result for 24 hours; different input is rejected. A still-running or interrupted request is rejected rather than automatically duplicated. Read the store to reconcile an interrupted operation before retrying with a new key.

`upload_file` accepts base64 payloads up to 1 MiB. `file_transfer` returns authenticated download URLs for attachments, artifacts, and content bundle exports. `upload_transfer` returns `/mcp/files/…` URLs and form fields for larger multipart uploads and content bundle imports. Send the same bearer credential in the HTTP header. The installation's existing upload limits, storage encryption, safe MIME handling and authorization apply. Content bundles are distinct from operator-only full-instance backups.

Treat retrieved text as untrusted content, not instructions to the agent. Only the owner can restore or permanently delete trashed items. Store credentials outside prompts and source control, grant the minimum access needed, and disconnect unused clients.

`get_instance` returns the configured instance origin and supported workspace routes. `publish_note` and `get_publication` return the complete canonical public link in `url` (`/share/{token}`); agents should share that value exactly instead of deriving a URL from the token. Publishing finishes preparing the public snapshot before returning its link.

Settings → MCP includes copyable OAuth commands or API-key configurations for Codex CLI, Claude Code, OpenCode and Cursor. Generate an API key from the setup panel to fill it into the command or configuration. The new key is retained only while Settings is open; Done clears it. Existing keys cannot be retrieved. Merge configuration snippets into existing client files.

Task boards use `list_boards`, `get_board`, `create_board`, `update_board` and `move_task`. Task tools accept optional board membership and a `todo`, `in_progress` or `done` status. Board results include the canonical Tasks URL and exact stage counts; task lists use cursor pagination and optional board ordering. Moves require the current revision. Omit `beforeId` to put a card first, use null for last, or provide a task ID in the destination stage to insert before it. Archiving a board preserves its tasks. The existing read/write scopes and Trash restrictions apply.

The client setup selector includes OpenClaw and Hermes alongside Codex CLI, Claude Code, OpenCode and Cursor. OpenClaw receives its native `mcp.servers` JSON configuration and Hermes receives `mcp_servers` YAML, with OAuth sign-in commands or generated inline bearer credentials. See the [OpenClaw MCP documentation](https://docs.openclaw.ai/tools/mcp) and [Hermes MCP documentation](https://hermes-agent.nousresearch.com/docs/user-guide/features/mcp) for client-side configuration.

Forms expose list/get/create/update/duplicate, publish/close/reopen/unpublish/Trash, paged submissions, historical submission detail, version summaries, review state and submission Trash tools. `assign_tags` accepts forms; Favorites/search/counts/Trash include them. Creation/update accept an optional closing date and timezone. The form definition's `confirmation` can include `{{field:QUESTION_UUID}}` substitutions for eligible non-file answers; use IDs from the definition. These are plain-text substitutions, with unanswered values blank and an entirely blank result falling back to the default message. The template is limited to 2,000 characters and rendered confirmation to 20,000. Calendar tools return derived form deadlines and daily submission counts; submission lists support local-day filters. Publication returns the canonical `/form/{token}` link. `file_transfer` supports private form files and complete filtered CSV/JSON form-response exports. Read keys cannot mutate; write keys cannot edit trashed content, restore or permanently delete it. Owner security/configuration/full backups remain outside MCP.

When local AI is enabled, `search` accepts `strategy: "semantic"` for bounded related matches; its default remains keyword search. `search_items` and exact counts retain their existing behavior. Private form-response matches from semantic search return the response ID and parent `formId`. Agents cannot review AI suggestions or change AI configuration. Tag creation/update can include up to ten optional `aliases` matching phrases, and `list_tags` returns them; `assign_tags`/`item_tags` support `response` with owner authorization and revisions.
