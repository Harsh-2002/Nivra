# Testing and verification

Use Node.js 24 and install CPU-only dependencies with `ONNXRUNTIME_NODE_INSTALL=skip npm ci`. Run:

```sh
npm run ai:assets
npm run typecheck
npm run lint
npm run format:check
npm run verify:branding
npm run verify:api
npm test
npm run build
```

Build verification checks the shipped indexing worker’s traced CommonJS dependencies, alongside private-data exclusion and required public-page/media assets. The automated suite uses disposable data and covers authentication, single-owner setup, recovery, passkeys, TOTP, persistence, search, pagination, revisions, files, encryption, backups, Calendar, Kanban, MCP and access restrictions. `writing-workflows.test.ts`, `task-planning.test.ts`, `bookmarks.test.ts`, `bookmark-reader-retirement.test.ts` and `capture.test.ts` cover revision fencing, journal periods, templates and linked tasks, schedules and recurrence, bookmark state, retired job/index cleanup, and bounded capture input. CI also builds Docker and runs `scripts/smoke-container.mjs` to check health, encrypted/plaintext onboarding, authorization, the single-owner invariant and persistence after container recreation. Release builds run that same check on native AMD64 and ARM64 containers before promoting the image. `release-policy.test.ts` rejects missing/failed CI, wrong commits, invalid date tags, incomplete architecture manifests and premature retirement of the active release. See [release policy](../CONTRIBUTING.md#releases). A passing suite is not proof of every physical browser/device behavior or an exhaustive security audit.

## Browser checks

Keep Playwright credentials and screenshots outside Git. Browser regression harnesses live in `scripts/browser-*.mjs`; inspect their required arguments before running them. Check desktop and narrow mobile, light/dark mode, focus and touch targets, overflow, loading/error states, unsaved edits and refresh/deep links. Test passkeys, push delivery with the app closed, and keyboard positioning on physical devices when those paths change.

`browser-accessibility.mjs` audits all workspace sections, Search/Settings, representative dialogs/selectors, authentication and public pages on a disposable server at port 3015. It requires `NIVRA_BROWSER_SESSION` for a saved synthetic owner session and uses axe-core for WCAG A/AA rules, alongside overflow, labels, input sizing and touch-target measurements. `NIVRA_AUDIT_ENGINE` selects Chromium, Firefox or WebKit; `NIVRA_AUDIT_WIDTHS` and `NIVRA_AUDIT_THEMES` select the viewport/theme matrix; `NIVRA_AUDIT_HEIGHT` checks short windows; `NIVRA_AUDIT_TOUCH=1` covers larger touch screens, and `NIVRA_AUDIT_SECTIONS` limits a height-specific run. `NIVRA_AUDIT_MODE=verify` fails on confirmed automated accessibility/layout findings; `layout` checks section overflow, calendar-year control overlap and the year grid’s target-size rule. `browser-accessibility-interactions.mjs` verifies keyboard navigation, focus restoration, mobile touch targets, calendar grid navigation, reduced-motion use and stable Settings height. `browser-accessibility-onboarding.mjs` requires an empty disposable server on port 3016 and checks guided onboarding before creating its synthetic owner. Keep synthetic fixture manifests and reports in the ignored review directory. The form-owner harness also exercises keyboard, mouse and native Chromium touch reordering. Review axe's incomplete results manually; automated checks do not certify screen-reader or physical-device behavior.

`browser-focus-stability.mjs` uses disposable port 3015, `NIVRA_BROWSER_SESSION` and `NIVRA_AUDIT_FIXTURES` from the accessibility harness. It verifies creation focus, repeated/composition Enter, pending and failed saves, Quick multiline submission, live board SSE, card/input identity during delayed refreshes across sections, and retained search selection. `NIVRA_AUDIT_ENGINE` and `NIVRA_AUDIT_WIDTHS` select browsers and widths; both themes are checked. `NIVRA_AUDIT_MODE=quick` limits a confirmation run to creation focus and Quick note/task/link submission. Its synthetic owner and port guards prevent use on a live installation.

`browser-tag-actions.mjs` uses the same disposable port and synthetic session. A fresh disposable instance creates its own test account and saves the session with restricted permissions. It checks sidebar tag creation/editing, cancellation and confirmed deletion, focus handoff from mobile navigation, selected-tag URL cleanup and preservation of tagged tasks. `NIVRA_AUDIT_ENGINE` and `NIVRA_AUDIT_WIDTHS` select browsers and viewports; both themes are checked against the rendered theme. CI runs Chromium, Firefox and WebKit against the production build at phone, tablet and desktop widths.

`node scripts/browser-overview.mjs` uses disposable port 3015 and the saved synthetic session. Its live check makes content changes in a second authenticated context and verifies SSE refresh, stable rows during delayed loading, canonical event/artifact/response navigation, private response-summary metadata and review counts, and conditional independent-card layouts at phone, tablet and desktop widths in both themes. It also checks separate bookmark and submission cards, natural page scrolling with no independently scrolling card lists, and private-answer exclusion from the snapshot. These checks exercise the additive Overview contract while retaining the existing content fields.

`node scripts/browser-foundations.mjs` exercises task planning, bookmark navigation and read state, Capture, and writing flows. It is restricted to localhost port 3015. Create a private run directory with `mktemp -d /tmp/nivra-foundations.XXXXXX`, set `NIVRA_DATA_DIR` to its `data` subdirectory and `NIVRA_BROWSER_SESSION` to a file in the run directory. The harness can create the synthetic `Review Owner` on an empty disposable instance, or reuse a matching session file. Set `NIVRA_AUDIT_ENGINE` to `chromium`, `firefox` or `webkit`. It checks desktop and phone widths, cleans fixtures through application APIs, and invokes `browser-writing.mjs`; planning assertions are shared from `browser-planning.mjs`. In WebKit, it reports the exact ignored `interactive-widget` viewport-hint diagnostic separately; other console and page errors remain failures. These checks do not certify screen-reader operation or physical-device keyboard behavior.

The accessibility harness includes template editing and preview, Journal date selection, calendar views and published notes. Interaction checks cover checklist loading failures and focus restoration, calendar task-list retry states, and keyboard navigation past event-occupied time slots. Bookmark navigation checks verify the original URL opens in a separate tab using a locally stubbed destination. Run in `verify` mode for confirmation.

## Performance checks

Use isolated, disposable data for benchmarks. `scripts/benchmark-library.ts`, `benchmark-boards.ts`, `benchmark-media.ts` and `benchmark-encryption.ts` provide synthetic workloads; read their argument and directory guards first. `scripts/monitor-scale.mjs` samples an explicitly supplied service cgroup. Record dataset composition, encryption mode, runtime mode, concurrent workloads and whether timings measure SQL or HTTP. Separate cold and warm results, idle CPU, service memory and worker/browser memory. SSE connection duration is not page latency. WAL permits concurrent readers with one writer, not multiple simultaneous writers.

`scripts/benchmark-queries.ts` creates an encrypted synthetic library covering notes, journals, tasks, bookmarks, artifacts, events, Forms, responses, tags, Favorites and Trash. Run `npx tsx scripts/benchmark-queries.ts /absolute/new-private-directory 100000` (1,000–300,000 content records); it rejects an existing output directory, removes its generated database/key after completion, and leaves a private JSON report. This measures synchronous service calls, SQL plans/call counts, first/warm timings, CPU time, database size and peak process RSS; it does not measure browser or network latency. Calendar runs deliberately invalidate the range cache. Compare identical dataset, storage and resource limits, and include cold typo/missing searches and broad/deep pages. `query-optimization.test.ts` verifies upgrade preservation, literal-search equivalence, broad search ordering, batched contexts and correctness after `ANALYZE`; `fuzzy-index.test.ts` compares typo candidates with exhaustive results.

`scripts/scale-fixtures.ts` can seed or extend an explicitly authorized installation. It requires `NIVRA_SCALE_ALLOW=dev-instance-fixtures`, an absolute private output directory and one owner; inspect its command and count options before use. Never run it against a real installation without authorization. This guard is for test tooling, not a supported application setting. Keep fixture manifests, account sessions, keys, raw measurements and audit reports private. Dated execution reports are not maintained as product documentation.

## S3 integration

Nivra uses S3-compatible object storage for files and optional backups; SQLite remains local. See [storage configuration](../README.md#configuration). Verify changes using a disposable MinIO/RustFS-compatible service, private bucket and isolated Nivra data:

1. Upload and fetch a file through authenticated routes; compare the original bytes and reject anonymous private access.
2. Check public snapshots use their copied attachments while the originals remain private.
3. Verify encrypted object envelopes and file/backup prefix separation.
4. Create and verify a full backup, then restore it into a new empty directory using the original key.
5. Recreate the test storage service with its original volume and confirm files and backups remain readable.

Dispose only of the test resources. Never restore over a running installation or substitute an existing storage service for a disposable test target.

Forms checks cover timezone-aware deadlines, daylight-saving day boundaries, expired submissions/uploads, derived Calendar entries and daily aggregates, public device themes, strict schemas, immutable versions, isolated anonymous submission/upload routes, safe retries, signature/quota/expiry handling, keyset paging while review/Trash changes, exact decimal aggregates, complete exports, private downloads, scope restrictions, tags/Favorites/search/Trash and encrypted backup restoration. `browser-forms.mjs` uses disposable port 3015 for public validation/uploads/retry behavior across Chromium, Firefox and WebKit, desktop/mobile and light/dark themes. `browser-form-owner.mjs` uses that server's saved synthetic owner session to exercise drag/keyboard/menu reordering, the closing-date picker, builder, preview, publication, summaries/review, deep links, Favorites, revision conflicts, two-tab SSE and completion refreshes during search changes. `browser-form-components.mjs` edits all 19 builder types and verifies settings, 44px controls, label gaps, saved data and reload persistence at phone, tablet and desktop widths in both themes. The owner/public matrices include small-phone and landscape viewports. All three scripts require disposable port 3015; owner/component checks use `NIVRA_BROWSER_SESSION` pointing to the saved synthetic session. Keep optional review captures and cookie files outside Git. Browser automation does not certify physical-device keyboard or assistive-technology behavior.

## Local AI integration checks

Prepare the pinned local pack with `npm run ai:assets`, then run `npm test` (including `ai-*.test.ts`). Tests use disposable encrypted directories: generation fencing, attachment/form-response visibility, worker crashes/deadlines/restarts, inter-process OS locks, approval/manual-tag merging, rejection history and read-only agent search. Missing/corrupt assets must fail closed. These are correctness checks, not evidence of user acceptance or new model-quality measurements.

Adaptive checks include migration 0046 upgrades without discarding stored vectors, opaque owner tag names, owner-example matching, label-only automatic evidence and abstention after corrections. The automation test exercises the actual note PATCH autosave path, pending-state manual readdition, content-edit/Trash cleanup, approved-tag retention, shared attachment support, task revision responses, reusable-topic deduplication, automatic creation limits, mode-change requeue and reviewed-response restrictions. The API test checks owner-only settings/proposals, revision conflicts, default-off behavior and agent denial. Keep fixed-model integration examples and any measured quality failures outside Git; they do not replace independent owner-vocabulary review.

Container CI runs native AMD64 and ARM64 source images with network disabled for AI/OCR smoke checks, alongside existing authentication, encryption, media and backup recovery checks. Resource tests must distinguish small inference smoke measurements from full indexed retrieval, bound both cache and query time, and report fallback at capacity/deadline limits. Before release, review System smart-feature controls, tag matching words and meaning-based search at mobile/desktop sizes in both themes, test private form responses/public pages/exports, and obtain human approval of representative owner-vocabulary suggestions. Never use a live data directory for these checks.

`node --import tsx scripts/benchmark-ai.mts 1000,10000` creates and removes an encrypted synthetic database. The optional `1000,10000,100000` run measures the capacity boundary. Its final argument is chunks per item: `100` (default) or `1` to exercise distinct-item metadata. Replicated vectors test resources, not retrieval quality. Report cold deadline fallback, separate cache preparation, five warm query samples, child CPU/RSS, idle CPU and encrypted storage size; never treat cache preparation as part of a three-second HTTP query. Container CI runs both layouts on native AMD64/ARM64 with one CPU, 1.5 GiB aggregate memory and no network. Warm failures and worker RSS above 512 MiB fail the check. Keep JSON output outside Git.

`scripts/browser-local-ai.mjs` uses the disposable port 3015 and synthetic `NIVRA_BROWSER_SESSION`. It checks alias editing, the separate Tag suggestions page, whole-card source opening, top-right dismissal, icon-only approval beside the suggested tag, compact selected-navigation/tag styling with current-page and pressed semantics, and automatic meaning-based workspace search when System smart features are enabled. It also verifies lexical fallback presentation, WCAG checks, overflow and touch controls across Chromium, Firefox and WebKit in both themes. The deterministic viewport/theme matrix isolates `EventSource` from uncontrolled background-job timing; its 30-card refresh case sends controlled completion bursts and checks that refreshes preserve visible suggestions and grid position while decisions refill the bounded batch without visible success/progress banners or stale-card restoration. A separate Chromium 320px check uses the authenticated live completion stream, indexes a second matching note, holds the actual suggestions request, and verifies the existing cards remain until a successful refresh response arrives. The live Overview stream has its own cross-context coverage in `browser-overview.mjs`. System settings expose enablement and indexing status, not the review list. `NIVRA_AUDIT_WIDTHS` selects viewports and optional `NIVRA_AUDIT_OUTPUT` stores private captures. Inspect actual captures as well as automated assertions. The frozen synthetic fixture tests conservative filtering against recorded final-evaluation scores; it does not measure new model accuracy or human acceptance.

`scripts/browser-post-setup.mjs` requires an empty disposable server on port 3016 and a private `NIVRA_BROWSER_SESSION` path. It completes password/encryption/recovery/configuration, verifies explicit starter/custom tag creation and duplicate handling, default-off smart features, opt-in persistence and disabled progression during saving, then checks saved progress and completion across Chromium, Firefox and WebKit at 320, 390, 768 and 1440 pixels in both themes. Separate platform cases verify iPhone, Android, desktop and standalone guidance plus a simulated browser install event. `NIVRA_SKIP_SETUP=1` reuses an existing disposable synthetic owner; `NIVRA_AUDIT_ENGINE`, `NIVRA_AUDIT_WIDTHS` and `NIVRA_AUDIT_THEMES` support bounded follow-up checks. Reload checks wait for workspace data and authenticated completion streams before and after navigation while retaining zero browser-error assertions. These checks do not certify physical-device installation. `onboarding-step.test.ts` verifies safe upgrade defaults, password/passkey setup, owner-only permissions and restart persistence; `onboarding-guidance.test.ts` covers default suggestions, selected-tag filtering, normalized aliases and platform/secure-context detection.
